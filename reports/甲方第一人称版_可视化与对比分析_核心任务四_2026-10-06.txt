三、我方用什么原理出图（任务书要求关键算法附原理说明）
===============================================================================

我方不引入新的三维渲染依赖，改用 matplotlib 的 Agg 后端做正交投影散点渲染：

1. 我把每个三角面的重心作为渲染采样点；
2. 我把重心投影到三个正交平面：XY 俯视、XZ 前视、YZ 侧视；
3. 破损区域按分类换成固定颜色，完整区域保持浅灰；
4. 修复前一行、修复后一行并排，甲方不需要装三维软件也能直接看图。

我为什么不用 Open3D 或 VTK 渲染：这两者都需要显卡上下文，在没有显示器的
Windows 机器上容易直接失败。Agg 后端是纯 CPU 光栅化，稳定、确定、可复现。

我为什么按正交投影而不是透视：甲方的验收关注“破了哪里、补了哪里”，
正交投影没有透视缩短，位置可以直接和 CAD 尺寸对上。

精确高亮的原理：
- 检测结果里 `missing` 区域保存的是完整参考模型上的三角面编号；
- `extra` 区域保存的是待检模型上的三角面编号；
- 我用这两个编号直接命中三角面，比只按包围盒高亮精确得多；
- 只有拿不到编号时（例如 STEP 修补报告只给 Face 编号），我才退回包围盒判定，
  并可用 `--face-features` 把来源 Face 的包围盒并起来还原区域。

跨模型不串色的原理：
- “修复前”一侧是待检模型（candidate），我只画 candidate 空间的区域；
- “修复后”一侧是参考/修复模型（reference），我只画 reference 空间的区域；
- 分类图也按空间分开出图，避免把两侧区域混在一张图上造成误读。

四、我方本轮修掉的两个真实缺陷
===============================================================================

1. 原子写入和 matplotlib 打架
   - 我方所有输出都走 `atomic_path`，临时文件名以 `.tmp` 结尾；
   - matplotlib 从扩展名推断格式，遇到 `.tmp` 直接报
     “Format 'tmp' is not supported”；
   - 我改成显式传 `format="png"`，问题消失，同时保留了原子替换。

2. 中文标题变成方框
   - matplotlib 默认字体 DejaVu Sans 没有中文字形，标题全是豆腐块；
   - 我把字体族设成 Microsoft YaHei / SimHei / Noto Sans CJK SC 回退链，
     并关掉 unicode_minus，中文标题正常显示。

五、我方真实验证（不是只跑单元测试）
===============================================================================

真实样例：训练集 8 号件，破损 STL（`8.stl`）对完整 STP（`8.stp`）。

第一步，我方跑检测：
```
python -m cad_inspector inspect "训练集\8.stl" "训练集\8.stp" ^
  --output-dir outputs\demo_visualize_inspect
```
得到 4 个区域：2 个 missing、2 个 extra，`status=review`。

第二步，我方跑可视化：
```
python -m cad_inspector.visualization_cli ^
  --before "训练集\8.stl" --after "训练集\8.stp" ^
  --regions outputs\demo_visualize_inspect\result.json ^
  --regions-kind inspection ^
  --output-dir outputs\demo_visualize ^
  --title "我方 8 号样件 破损区域检测与修补对比"
```

输出：
- `comparison_before_after.png`（2 行 × 3 视图，约 300 KB）
- `region_classification_candidate.png`（待检模型分类标记）
- `region_classification_reference.png`（参考模型分类标记）
- `visualization.html`（自包含，PNG 以 base64 内嵌，约 517 KB）
- `visualization.json`（清单：schema `visualization-1.0`、分类统计、区域明细）

我方人工看图确认：中文标题、三个正交视图、修复前后两行、分类图例
（extra / missing）都正常渲染，没有方框、没有重叠。

六、我方必须如实说明的一个检测质量问题
===============================================================================

我方在真实样例上发现，这一对的检测结果本身是“整件都在报”：
- 配准质量 `warning`，平均残差 `0.370 mm`，P95 残差 `0.862 mm`；
- 默认阈值是 `0.150 mm`，残差比阈值还大；
- 全局指标 missing_area_ratio `0.844`、extra_area_ratio `0.852`。

结论：这对模型（扫描 STL 对 CAD STP）配准残差远大于默认阈值，所以几乎
整个模型都被标成破损。这不是可视化的缺陷，而是检测阈值对模型尺度不敏感
暴露出来的问题。我为了不让甲方误读，专门在图上加了一行真实副标题：
“检测状态 / 配准质量 / 平均残差 / 阈值”，甲方一眼能看出这张图的高亮范围
是受配准残差影响的。

后续专项：我方需要把固定阈值升级为“按模型尺度自适应的阈值”，并在这类
扫描-对-CAD 的样例上重新标定，才能让这一对的检测结果可用。我本轮不把它
写成已经解决。

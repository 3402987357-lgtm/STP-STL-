我方做连续性质量验收，顺带修掉一个会把"没量过"显示成"完美0度"的bug
日期：2026-10-11
项目根目录：D:\STP_STL_Missing_Region_Recognition

一、这轮要做什么

上一轮我打开了 `allow_nonplanar_surface_candidate`，训练集/7 从 REVIEW 变
SUCCESS。但我如实留了个限制：**它是靠"待复核"的曲面填充候选成功的，我拿不
出几何质量证据**（G1/G2 实测是 NOT_VERIFIED）。这轮补上。

二、**先做了一个对得上的观察**

    训练集/7（**新** SUCCESS）：G0 VERIFIED / G1 NOT_SATISFIED / G2 NOT_VERIFIED
    训练集/8（**一直** SUCCESS）：G0 VERIFIED / G1 NOT_SATISFIED / G2 NOT_VERIFIED

**两者完全一样。** 这说明打开开关**没有降低质量标准**——新成功的件拿到的
证据水平，和原本就成功的件是同一档。这回应了我上一轮的顾虑。

三、做的实现：把**实测数值**汇总进诊断

原先 diagnostics 只有 `VERIFIED / NOT_SATISFIED / NOT_VERIFIED` 这类状态，
甲方看到"G1 不达标"却不知道**差多少**——是 6 度还是 60 度，处置完全不同。
数值在环级结果里本来就有，只是没汇总。我加了 `continuity_measured`，给
G0/G1/G2 各自的**最坏值（max）与平均值（mean）**。

四、**加了数值之后，立刻暴露一个 bug**

汇总出来第一行数据就自相矛盾：

    训练集/7：G1 实测 **0.0 度**，门限 **5.0 度**，状态却是 **NOT_SATISFIED**

0.0 <= 5.0 本该通过。**"实测完美却判未通过"只能是数据有问题。** 我去查判定
代码，根因是（step_hole.py）：

    g1_complete = bool(source_face_ids)        # 第 2004 行
    g1_verified = g0_verified and g1_complete and ...

**没有源面可比较时 `g1_complete` 一开始就是 False，比较循环一次都没跑**，
而 `g1_max_angle` 的初值是 **0.0**——于是输出"法向夹角 0 度"，看起来像
**完美贴合**，实际是**一次都没量**。

修复：没真量过就必须是 `None`。这个处理跟代码里**已有的** G2 处理是同一个
道理（2192-2196：G1 未过时 G2 曲率置 None，理由写着"留着会让人拿它去当结论"），
我只是把同一条规矩补到 G1 自己身上。

    修复前：G1 measured_count=1, max=**0.0**（假象）-> 与 NOT_SATISFIED 矛盾
    修复后：G1 measured_count=0, max=None     -> NOT_VERIFIED（"没量过"，自洽）

**值得记的一点**：这个 bug 是我**加了数值汇总之后**才发现的。原先只报状态，
它藏得好好的；一旦把数字摆出来，矛盾立刻刺眼。**把数字暴露出来本身就能抓 bug。**

五、验证

    全套相关测试：**60 passed**
    全量真实破损基准：**8/11 = 0.727273**（与上轮持平，未受影响）

六、这轮回答了什么、没回答什么

**回答了**：打开曲面填充开关**没有降低**质量标准（新成功件与原有成功件证据
同档）；G1/G2 的实测数值现在可见。

**没回答**：`deviation`（补面相对原始设计的偏差）**仍然是
NOT_AVAILABLE_NO_REFERENCE_SURFACE**——因为没有参考面。而**参考面本质上拿
不到**：输入就是破损件，没有"原始完整版"可比对。所以这条路不是没做，是
**这个语料下不可能做**，除非语料提供参考答案。

七、我保留的限制

1. **G1/G2 的"通过"仍然很少**：训练集/7、训练集/8 都是 G1 NOT_VERIFIED
   （没量到，因为没有可比较的源面）。我修的是"别把没量说成完美"，
   **没有**让更多件真的量到 G1。
2. **测试集/1 与训练集/1 仍是 REVIEW**，未解决。
3. 我只验了两个件（训练集/7、训练集/8）的数值变化。
4. `continuity_measured` 是**新增字段**，下游若有解析 diagnostics 的代码，
   需要能容忍新键。

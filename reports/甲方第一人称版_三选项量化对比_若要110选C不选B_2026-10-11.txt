一、三个选项的实测结果（都是 monkeypatch 实验，**生产代码未改**）

    A. 按**缝总长**、阈值 0.05（**现状**）  -> **10/11 = 0.909091**
    B. 按**单条最大**、阈值 0.05          -> **11/11 = 1.0**
    C. 按**缝总长**、阈值 0.15（本轮新试） -> **11/11 = 1.0**

三个选项下，**其余 10 件全部不变**，只有训练集/1 在 B/C 下 False -> True。

二、B 和 C 的差别（这是本轮的关键）

    B："只要**每条**缝都小于 0.05，就当它已封闭"
       -> 训练集/1 有 **52 条**缝，B 只看"每条都小"，等于把"缝很多但每条都很小"
          说成"**没有缝**"。

    C：仍按**总长**判（52 条缝**照常累加**），只是把阈值从 0.05 放宽到 0.15
       -> 训练集/1 总长 **0.140364 mm <= 0.15** -> True
       -> **"缝多"这件事仍被计入**，只是承认"总长 0.14 mm 的微小缝也算封闭"。

**所以若要 11/11，我建议选 C 而不是 B**——C 没有把 52 条缝说成没有缝。

三、**但 C 也没解决"两套口径打架"**（这点 C 和 B 一样，我必须说清）

训练集/1 的 `repair_status` 仍是 **REVIEW_REQUIRED**——修补器**自己说"这个件
需要人工复核"**。无论 B 还是 C，基准都会同时判它 `closed=True`（"补成封闭
实体"）。甲方会看到同一个件一边说"要人工看"、一边说"已封闭"。

**这个矛盾是改判据本身带来的，B 和 C 都躲不掉。**

四、我的建议：**保持现状（A，10/11）**

理由（与上一轮一致，C 没有消除它们）：
1. 避免"自报 REVIEW / 基准说已封闭"的矛盾。
2. C 虽然比 B 诚实，但**仍然是放宽判据本身**——而 10/11 那次是**填回缺失的
   测量值**（判据一字未改），性质不同。
3. 0.15 这个数是我**为了让训练集/1 刚好通过**挑的（它总长 0.140364）。
   **为一件去调阈值，有"对着答案改卷"的味道**，我不推荐这么做。

五、若你决定要 11/11

选 **C**，并且我建议把阈值写成"几何容差的 3 倍"而不是硬编码 0.15，同时把它
做成显式配置项而不是藏在判据里。**目前生产一字未动，你定了我再落地+补测试。**

六、我保留的限制

1. **三个选项都是实验结论，均未落地。**
2. C 的实现是**实验 hack**：我改不动判据内部的阈值（它在 `run_real_case` 里、
   monkeypatch 不到），所以用"量出的长度乘 1/3"来等价模拟 `x <= 0.15`。
   **真要落地必须直接把阈值提出来**，不能这么写。

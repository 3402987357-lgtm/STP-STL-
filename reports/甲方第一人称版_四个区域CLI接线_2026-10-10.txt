一、我发现了什么

目标里有"按不同的区域部分来实现这个代码，补充所有的需求"。这一轮我
做了一次全局核对，用 `rg` 全库搜每个模块的引用，找出**写了但没人能
调用**的区域 CLI：

    bom_cli            -> 引用数 0
    dataset_cli        -> 引用数 0
    feature_cli        -> 引用数 0
    visualization_cli -> 引用数 0

这四个模块各自都有完整的 `_build_parser()` + `main(argv)`，但**一个都没
挂到 `cli.py` 上**——用户根本调不到。这是目标里"按区域实现"的真实缺口。

（我另外查到 `learning/model.py` 也是引用数 0，但它是**设计如此**：可选
的 torch 增强，导入延迟到真正构造模型时，缺 torch 只让这一个函数失败、
不影响几何基线。它不是缺口，我没动。）

二、我怎么接的（用 REMAINDER 透传，不重复造参数表）

    # 注册
    for _name, _help in (
        ("bom", ...), ("dataset", ...),
        ("feature-classify", ...), ("visualize", ...),
    ):
        _sub = subparsers.add_parser(_name, help=_help)
        _sub.add_argument("rest", nargs=argparse.REMAINDER, ...)

    # 分发（放在 if 链最前面，早返回）
    if args.command == "bom":
        return int(bom_main(list(args.rest)))
    ...

我为什么用透传而不是在 `cli.py` 里重写一遍参数：每个区域 CLI 已经有
自己的完整参数表和帮助文本，在主 CLI 再写一遍就是**两套要同步维护的
参数表**，改一处忘一处必然出错。透传让每个区域 CLI 自己解析自己的参数。

三、我怎么验证透传真的生效

光看"子命令注册上了"不够——要证明**参数是被区域 CLI 自己接管的**。
我用"报错方是谁"来验证：

    $ python -m cad_inspector bom
    usage: __main__.py [-h] [--output-dir OUTPUT_DIR] [--master-data MASTER_DATA]
                       step
    __main__.py: error: the following arguments are required: step

    $ python -m cad_inspector bom nonexist.stp --output-dir outputs\_probe_bom
    [ERROR] 我方 BOM 解析失败：我找不到输入文件：nonexist.stp

报错的是 **bom_cli 自己**（它认 `--output-dir`、认 `step` 位置参数），
不是主 CLI。透传生效。

四、我踩的一个坑（以及为什么改掉）

我第一版测试用 `subprocess` 起一个新进程去调 `python -m cad_inspector
bom`。单独跑能过（我手上有 `PYTHONPATH=src`），**全量跑就挂**
（1 failed / 465 passed）——因为全量环境里没有这个环境变量。

改成直接调 `bom_main([])` 并捕获 stderr：

    err = io.StringIO()
    with contextlib.redirect_stderr(err):
        with pytest.raises(SystemExit):
            bom_main([])
    assert "step" in err.getvalue()

教训：**测试不该依赖外部环境变量**，它在一个环境能过不代表在另一个
环境能过。

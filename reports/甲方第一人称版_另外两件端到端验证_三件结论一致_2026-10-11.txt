我方补测另外两件的端到端效果：BRep能修好但status都没变，三件结论一致不修
日期：2026-10-11
项目根目录：D:\STP_STL_Missing_Region_Recognition

一、我这轮补的是什么

全量普查发现 3 个件各有一个坏面（测试集/2 面#133、训练集/1 面#633、
训练集/4 面#14），病因同构。但我只在 **训练集/1** 上测过端到端（修一遍后
环数 44->76、变糟）。**另外两个件没测**。这一轮补上。

**我这一轮特别修掉了上一轮那个坑**：上一轮脚本只判断"有没有变化"就自动
打印"值得实现"，没判断**方向**（44->76 明明变糟却被当成改善）。这一轮我把
判定写死成三条**显式指标**，并且**不允许**脚本下"值得做"的结论。

二、结果

    测试集/2
      整件 IsValid: False -> **True**
      status:       SUCCESS -> **SUCCESS**（没变）
      环数:         9 -> **13**（**变多**）
      朝好的方向: BRep 由无效变有效
      朝坏的方向: **环数变多 9->13**

    训练集/4
      整件 IsValid: False -> **True**
      status:       NO_ACTION -> **NO_ACTION**（没变）
      环数:         0 -> 0（无变化）
      朝好的方向: BRep 由无效变有效
      朝坏的方向: 无

三、一个新发现：连修效应**不是普遍规律**

上一轮我查出"训练集/1 要**连修两遍**才能变有效，单遍不行"，并因此更正了
前面"0.06 起能修好"的结论。

**但这一轮两个件都是单遍就见效**（MaxTol=0.06 修一遍，IsValid 都从 False
变 True）。所以"必须连修"**不是普遍规律**，很可能是 **训练集/1 特有**的。
我把上一轮那个更正**收窄**到训练集/1，不外推到全部件。

四、端到端结论：三个件一致 —— **不建议修**

    件         BRep 变化      端到端 status     环数变化
    训练集/1   （单遍修不好）  REVIEW -> REVIEW  44 -> 76（变糟）
    测试集/2   False -> True   SUCCESS -> SUCCESS  9 -> 13（变糟）
    训练集/4   False -> True   NO_ACTION -> NO_ACTION  0 -> 0（无变化）

**三个件的端到端 status 全都没变。** BRep 那一项"变有效"**没有传导到修补
结果**——这正是我前面付出过代价学到的：**单件指标变好 != 端到端结果变好**。

而且 `测试集/2` 环数从 9 涨到 13，**引入了新的自由边**（朝坏的方向）。

**所以"修坏面"目前没有端到端收益，且可能引入新自由边。我的建议仍是
保持不修。** 这个结论现在有**三个件**的一致证据支持，不再是单个件的推断。

五、我保留的限制

1. **坏面仍未修**（建议不修）。本轮**无代码改动**。
2. **我只用了 MaxTol=0.06 这一档**测这两个件，没扫其它档位。
3. "环数变多"我判断为朝坏的方向，但**没有进一步查**那些新环是什么、
   是不是同样被判为公差裂缝（若是，实际影响可能更小）。
4. 训练集/1 那个件我没有用"连修两遍"的版本测端到端，所以**连修的端到端
   效果仍然未知**。
5. 只测了这 3 个有坏面的件。

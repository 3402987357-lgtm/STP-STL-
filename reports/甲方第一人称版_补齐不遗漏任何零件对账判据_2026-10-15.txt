补齐"不遗漏任何零件"对账判据，并修掉多 Solid 拆分导致的重复计数
日期：2026-10-15
项目根目录：D:\STP_STL_Missing_Region_Recognition

一、我为什么要做这一块

甲方要求"不遗漏任何零件"。我核对时发现：这条要求**此前没有任何判据**——
BOM 少算或多算几个零件都不会报错，看表也看不出来。

我去核了真实产物，它确实对不上：

    mould_04：装配树 156 个实例，而"数量"列合计 159 —— **多 3 件**

二、根因

多 Solid 拆分会把一个装配节点展开成多行。一个节点含 3 个 Solid 时被拆成
3 行，这 3 行**各自继承了原节点那 1 个 occurrence**，于是同一个实例被计了
3 次。零件种类是对的（48 行），但"总件数"虚高 3 件。

采购按这个数下单就会多买 3 件。而它在 BOM 表上完全看不出来——
3 行的"实例编号"列都是 `label:14`，看不出是同一个。

三、我做了什么

1. **修掉根因**：拆分行改用带 `#solid_NNN` 后缀的**派生** occurrence id
   （`label:14#solid_001` / `_002` / `_003`）。既保留可追溯（能看出是从
   哪个实例的哪个 Solid 拆的），又不会重复计数。

2. **把"不重不漏"变成可对账的判据**：新增
   `reconcile_bom_completeness`，拆成两条口径分别比对，写进
   `diagnostics.completeness`；对不上时整份报告升级为 REVIEW_REQUIRED
   并给出警告。

   两条口径分开是有意义的：

     - **覆盖口径（查漏）**：把 id 上的 `#solid_NNN` 后缀剥掉再取集合，
       集合大小 == 装配树实例数。剥后缀是因为拆分行本就指向同一个装配
       实例，不剥会把"覆盖数"抬高，反而掩盖真正的漏计。
     - **件数口径（查重复）**：各行 quantity 之和 == **预期槽位数**
       （= 各计量单元实例数之和），不是拿装配树实例数比。
       拆分会让 1 个节点展开成 N 行，所以用装配树实例数去比件数
       **永远不会相等**，那条判据就只会一直报假警。

我排查后确认是**两个门禁并发执行**造成的假红：当时有 2 个

九、补齐二：把"0 命中大类"的原因说清楚（同日做完）

任务书要求按 8 大类分类，实测真实数据上 **7 个大类恒为 0**。
我查下去发现：这些 0 有**两种完全不同的含义，此前报告把它们混在一起**。

**第一种是我方能力缺口**（成型零件 / 侧向抽芯零件 / 冷却浇注零件）：
这 3 类**只有名称规则能命中**，几何规则永远给不出它们的候选。
而实测 509 个不同零件名里有 **363 个是哈希串**
（形如 `52561FBC24A736ws#solid_001`），根本没有关键词可匹配。
这类 0 **不代表模具里没有这类零件**。

这尤其危险：**成型零件（型腔/型芯）是任何一套注塑模的定义性零件**，
它报 0 几乎必然是漏识别，而不是"这台模具没有型腔"。
甲方若把"成型零件 0 件"读成"没有型腔型芯"，结论就反了。

**第二种是几何真歧义**（模架 / 导向 / 顶出 / 紧固件）：几何规则确实
给出了候选，但同时存在跨大类的竞争候选，交集为空，我方不硬下结论。
实测 341 个未分类件的候选组合只有 4 种，其中 **233 个是"板件/结构件
+ 模架件 + 辅助结构件"三选一**，几何上确实分不开。

我新增 `summarize_category_coverage` 和常量
`NAME_ONLY_PART_CATEGORY_GROUPS`，把两种 0 分开写进
`diagnostics.category_coverage`，并在报告里显式警告：

    我方无法识别以下部件大类（缺少零件名称或主数据，不是模具里没有）：
    成型零件、侧向抽芯零件、冷却浇注零件。这些大类的 0 命中不等于不存在，
    需要甲方提供名称规范或主数据。

mould_04 实跑结果：3 类判为能力缺口，4 类判为几何歧义，
**每个 0 都带原因文案，不出现裸 0**。

反向验证：把能力缺口集合清空后测试如期转红，还原后转绿。
新增 2 个回归测试，全量 **634 passed**；10/10 交付产物重新生成后
全部带 `category_coverage`，且对账仍为 PASS、dup 仍为 0。

**我没有真正提高分类命中率。** 这一轮做的是把 0 的**原因说清楚**，
不是让那些零件被认出来。要真正命中成型零件/侧向抽芯零件/冷却浇注零件，
仍需甲方提供零件名称规范或主数据——这是输入条件的缺口，

一、合成基准现状（20 个 case）

    17 SUCCESS / 3 REVIEW_REQUIRED = 17/20 = 0.85

二、那 3 件是谁、卡在哪

    测试集/9#face3、训练集/5#face1、训练集/5#face3

**它们的 warning 一字不差，是同一个失败模式**：

    1. "我发现补面后仍有开放边界，当前 STP 只能作为人工复核候选。"
    2. "我生成了局部补面候选，但输出没有通过封闭实体质量门禁。"
    3. "我因输出质量门禁未通过而保留原始输入，不把待复核 Shape 写成正式
       修复结果。"

也就是说：**补面是生成出来的，但输出带残余开放边界 -> 封闭实体质量门禁拒掉
-> 不写出文件 -> 落 REVIEW_REQUIRED。**

三、一个有用的对照

成功件里**有不少 `out_boundary` 不为 0 却仍是 SUCCESS** 的：

    测试集/10#face1  out_boundary=1  SUCCESS
    测试集/11#face3  out_boundary=1  SUCCESS
    测试集/8#face3   out_boundary=2  SUCCESS
    训练集/0#face3   out_boundary=1  SUCCESS

说明判据**并不要求"边界边数为 0"**，而是看**残余缝总长是否 <= 容差**。
所以这 3 件被拒，是因为它们的**残余总长超过了容差**——不是"有缝就拒"。

四、**顺带发现一处口径不一致（我认为该修，但属评分口径，等你定）**

上一轮我修了一个误判：真实破损路径里，**未写出文件时 after_* 全为 None**，
导致本来就完好的件被判"未封闭"。我把它改成"**未写出 = 原样保留 = 退回量
输入件**"（`run_real_case`）。

**但合成路径（`run_case`，249 行）我还是原样**：

    if output_path.exists():      # 只有写出才量
        ...

**同一件事在两条路径上口径不一致。** 后果：这 3 件未写出 ->
`after_gap_mm` 为 None -> 在合成路径里量不到它们的真实残余长度，**我们连
"超了多少"都不知道**，只能看到"门禁拒了"。

**要不要把同样的修正应用到合成路径，我等你定**——它同样是评分口径，
而且会让这 3 件的 `hole_closed` 有机会变成 True（取决于它们真实的残余
总长是否 <= 容差）。

一、我做了什么（这次真的改了代码）

前面几轮我用实验证明：生产路径（`ShapeFix_Shell`）上调 `MaxTolerance` 能让
3 个 BRep 无效件的 Shell 变有效（测试集/2、训练集/1 需 0.06；训练集/4 需
0.05），且**没有任何单一档位能同时覆盖三个**。

所以我改了 `src/cad_inspector/repair/step_hole.py`：
- 新增档位常量 `（0.05, 0.06, 0.1, 0.2, 0.5）`；
- `_fixed_shell` 改为**按档各修一遍、返回候选列表**；
- `_try_build_solid` 里展开成候选序列，**原壳优先**，逐个试、**有效才采用**
  （沿用那里原有的保护模式）。

二、验证：改完 36 passed，但基准无收益

- `tests/test_step_repair_sampling.py + test_step_repair_ocp.py`：**36 passed**
  （没有破坏现有行为）。
- 单机验证 `训练集/1`：**无变化**（仍 REVIEW_REQUIRED、44 个区域）。
  原因想清楚了：它的 44 个环全是**公差裂缝**、前置判定就拦下，**根本没走到
  建 Solid 那一步**，而我改的是补面之后的环节。
- 全量真实破损基准：**7/11 = 0.636364**。

三、我一度判断"改动把件弄坏了"，这个判断是**错的**

我看到 7/11，就写"改动让测试集/1 和训练集/7 从 SUCCESS 退化成
REVIEW_REQUIRED，必须回滚"。**我回滚了**，但回滚后重跑**仍是 7/11**。

**改动前后都是 7/11 -> 改动不是退化的原因。**

真正的差异在**参数**：我把旧产物（9/11）和新跑（7/11）的 config 一比：

    参数                                旧产物(9/11)  新跑(7/11)
    allow_nonplanar_surface_candidate     True          False
    allow_triangulated_boundary_candidate True          False
    max_planarity_error_mm                0.05          0.25
    preserve_original_on_failure          False          True

**旧产物那次是开着非平面/三角化候选跑的**，我这次用的是**基准默认**。
**两者不同参数，9/11 与 7/11 本就不可比**——我却拿它当了改前基线。

四、回滚后的决定性验证

我把代码回滚成原样（`_fixed_shell` 恢复单壳返回、`_try_build_solid` 恢复
`(shell, _fixed_shell(shell))`），然后**用旧产物那套参数重跑**：

    **hole_closed_ratio = 0.818182（9/11），SUCCESS 9** <- 与旧产物一致

**这证明代码已正确回到原状态**，9/11 在对应参数下完整重现。

五、最终结论

1. **我的多档改动没有带来收益**：在真实破损、默认参数口径下，改动前后
   **都是 7/11**。所以我**保持回滚状态**（不引入没有收益的复杂度）。
2. **我上轮"改动把件弄坏"的判断是错的**，已更正。
3. **当前代码 = 回滚后的原样**，且已验证 36 passed、旧参数下 9/11 重现。

六、教训（我写进代码注释里了）

1. **对比基线必须同参数**。我拿不同参数的旧产物当"改前基线"，差点冤枉
   自己的改动，也差点掩盖真正的原因。
2. **"通过有效性检查" ≠ "结果被接受"**。多档候选每一档都过了 `IsValid`，
   但过关不代表结果更好——较宽档位能造出通过检查的实体，却仍可能让后续
   流程判为需要复核。我当初把这两件事当成一件。

七、我保留的限制

1. **改动已回滚**，所以"多档 MaxTolerance"**没有落地为产品能力**。
2. **在旧参数（开非平面候选）口径下，多档改动是否有收益，我没测**——
   我只测了默认参数口径。这是未验证的可能。
3. `训练集/1` 的零长边坏面仍未修；BRep 无效的具体分类仍未拿到。
4. 我只跑了 4 个件做容差实验。

二、我方把项目拆成的阶段（长计划骨架）
===============================================================================

阶段 1：数据与清单
- 把甲方给的训练集/测试集/模具 STEP 全部登记成 manifest（JSON + CSV）。
- 做输入校验、单位归一化（厘米 STEP 自动换算到毫米）、文件格式白名单。

阶段 2：STEP/STP 实体读取与 B-Rep 特征
- 用 OCP（OpenCASCADE Python）读取真实 B-Rep：Face/Edge/Wire/Shell/Solid 统计。
- 逐 Face 输出曲面类型、面积、法向、包围盒、Edge 端点 Vertex 坐标。

阶段 3：区域分类与工程特征
- 识别上下面、侧壁、倾斜面、Face 邻接候选。
- 输出台阶、圆柱/孔、R 角、拔模方向等工程候选证据。
- 把区域边界做成可审计链路：Edge 长度 → 候选 Wire 周长 → 主 Wire 选择 →
  闭合环层级（外环/内孔/相交/无法判断）→ 二维投影面积 → 冲突复核。

阶段 4：分型线与分型面
- 从 STL 网格提取水平截面分型线，并给出诊断用平面分型面。
- 明确区分“候选分型线”和“最终封闭分型面”，不越界宣称。

阶段 5：缺失区域检测与修补
- 用 STEP 完整模型与破损 STL 做几何差异比对，输出缺失区域候选。
- 对满足安全条件的简单孔洞做局部修补（STL 网格与 STEP 开放边界两条路径）。

阶段 6：标注、训练与评估
- 提供真实标注清单校验和跨 split 数据泄漏门禁（文件级）。
- 用合成删除面标签评估缺失区域基线，产出可复现指标。

阶段 7：GUI 与交付
- 当前只做到命令行与结构化输出；GUI、安装包、生产部署属于未完成范围。

五、我方做过的极端测试与多轮排查（真实记录）
===============================================================================

我方按“先复现、再修根因、再加回归”的方式迭代，历轮全量测试数量演进：
185 → 196 → 198 → 209 → 210 → 219 → 225 → 226 passed。

已修复的代表性真实缺陷（都有对应回归测试）：
1. 大型 CSV 证据单元格超过 Python csv 默认 131072 字符上限 →
   审计器与测试同步提高 field_size_limit 到 64 MiB，并加回归。
2. 环关系证据写 CSV 超过 Excel 32767 字符上限 →
   JSON 保留完整证据，CSV 改为 30000 字符以内可扫描摘要。
3. 多环投影各自按自身中心投影，导致相交环被误判为包含 →
   改为所有环共享同一全局原点与全局平面轴。
4. 零三角面的合法 Binary/ASCII STL 报出与事实不符的错误 →
   统一给出“不包含任何三角面”的清晰错误。
5. InspectionConfig 静默丢弃未知键、参数名写错悄悄退回默认 →
   未知键直接报错并列出名字。
6. 过期 __pycache__ 抢占导入导致“源码正确却报缺参”的假失败 →
   标准测试入口先清字节码并禁止写字节码。
7. 清理白名单与实际日志名不一致，step_engineering\_regeneration_mould_04.log
   永远清不掉（4 个再生日志约 81 MB）→ 改为 *regeneration*.log 兜底。

极端输入覆盖：空文件、错误扩展名、截断的 Binary/ASCII STL、零三角面网格、
超大字段 CSV、重复 JSON 键、CSV 列数不齐、空输出目录、坏配置传入 --config、
13 个子命令 --help、8 条坏输入 CLI（全部退出码 2 且无 traceback）。
